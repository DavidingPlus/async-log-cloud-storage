# 文件列表接口与前端渲染计划

服务端已提供列表、上传和下载接口。Web 客户端已独立提供页面，通过 `GET /api/files` 获取数据并渲染，上传成功后刷新列表。Web 浏览器验收待完成。

## 目标与范围

服务端负责文件存储、元数据和 HTTP 接口。Web 和桌面客户端各自提供界面，并通过相同的接口获取数据。Web 页面的静态资源由前端部署提供。

按两个阶段顺序实施：先完成服务端接口和现有 Web 页面的改造，并测试验收 Web 前端；通过后再开始 LarkSDK 桌面客户端开发。本计划重点描述第一阶段，桌面端按其实施方案另行开展。账号、删除、批量操作及断点上传不属于本次范围。上传和下载沿用现有协议。

## 文件列表接口

新增 `GET /api/files`，由 `DataManager::getAll()` 获取元数据，成功返回 `200`，`Content-Type: application/json; charset=utf-8`：

```json
{
  "files": [
    {
      "name": "example.txt",
      "storage_type": "uncompressed",
      "stored_size_bytes": 1234,
      "modified_time": "2026-11-17 15:30:00",
      "download_url": "/download/example.txt"
    }
  ]
}
```

- `files` 始终为数组，空列表为 `[]`；客户端不依赖顺序。
- `name` 为 UTF-8 文件名；`storage_type` 为 `uncompressed` 或 `compressed`。大小是非负整数，单位字节，表示实际存储大小，压缩后不保证更小。
- `modified_time` 为服务端本地时间，格式 `YYYY-MM-DD HH:MM:SS`，不含时区；前端原样显示，不用于跨时区计算。
- `download_url` 是以 `/` 开头的服务根路径，不含主机或磁盘路径；按现有上传成功响应对元数据 URL 的编码规则生成。客户端原样使用，避免重复编码或解码。
- `POST`、`HEAD`、`PUT`、`DELETE` 请求此路由时返回 `405` 和 `Allow: GET`。`OPTIONS`、`TRACE`、`PATCH` 由 libevent 直接返回 `501`。元数据处理或 JSON 序列化失败返回 `500`。使用现有 JsonCpp 和 `JsonUtil` 生成 JSON，响应不包含磁盘路径。

列表沿用下载处理的存储目录判断和原网页的时间格式。任何记录的存储目录无法识别、文件名无效，或下载 URL 不符合当前前缀和单个文件名的路径格式时，整个请求返回 `500`。列表基于已加载的元数据，数据文件是否仍在磁盘上由下载时检查。目录或下载前缀变更后的历史数据迁移不在本计划内。

## 实施步骤

1. 在 `src/server/service.h`、`service.cpp` 中新增列表处理函数，在通用请求分发中注册 `/api/files`。复用现有元数据、时间格式、URL 编码及存储类型判断，保持上传和下载行为。
2. Web 客户端在 `src/client/web/index.html` 中渲染列表。页面加载及上传成功后同源请求 `/api/files`，显示加载中、空列表和请求失败状态。使用 DOM 文本展示文件名，下载使用接口返回的编码路径。
3. 将 Web 页面移至客户端目录，移除服务端首页路由、HTML 生成和资源同步。服务端安装包包含程序、配置和运行依赖。同步接口测试与部署文档。
4. 完成下方服务端自动化测试及 Web 前端测试和验收，记录结果并修复发现的问题。
5. 第一阶段验收通过后，开始桌面客户端开发。桌面端按同一契约读取列表，保存每行的 `download_url`；不信任绝对 URL 或跨站跳转。客户端 UI、后台请求、文件对话框和下载安全写入另按客户端实施方案完成。

## 路由和部署约定

目前下载前缀优先匹配，配置只要求前后有 `/`。例如 `/api/` 可能让 `/api/files` 同时成为下载路径和新接口，简单调整优先级会改变已有文件的下载行为。沿用维护者保证下载前缀不与固定路由冲突的约定，将 `/api/files` 纳入保留路由；实施前检查实际配置及历史 URL，冲突时先由维护者处理或迁移，不静默覆盖旧下载。默认 `/download/` 不冲突；测试覆盖默认前缀和非冲突的自定义前缀。

Web 静态站点提供首页并同源代理 `/api/files`、`/upload` 和配置的下载前缀到服务端。客户端请求使用根路径。服务端默认监听 `127.0.0.1:7081`，跨机器访问需配置监听地址和网络；不可信网络需正确配置 HTTPS 及证书验证。当前服务没有身份认证，前端不能替代服务端访问控制。
